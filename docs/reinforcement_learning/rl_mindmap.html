RL Fundamentals

Core concepts forming the foundation: Agent-Environment interaction, MDPs, returns, and the exploration-exploitation tradeoff.

5 concepts
▼

Agent-Environment Interface

Core

The fundamental interaction loop defining how an agent perceives, acts, and learns within its environment.

This is the central abstraction of RL — everything builds on this loop.

  • Agent observes state sₜ from environment
  • Agent selects action aₜ based on policy π(a|s)
  • Environment returns reward rₜ₊₁ and next state sₜ₊₁
  • Objective: Maximize cumulative expected rewards over time
Why This Matters

Unlike supervised learning with fixed datasets, RL agents must balance gathering information (exploration) with leveraging known good actions (exploitation). The sequential nature creates credit assignment challenges — which past action caused this reward?

Four Elements of RL

Core

Policy, Reward Signal, Value Function, and Model — the building blocks of every RL system.

Understanding these distinctions clarifies why different algorithms exist.

  • Policy (π): Maps states to actions — defines agent behavior
  • Reward Signal: Immediate scalar feedback each timestep
  • Value Function: Expected long-term cumulative reward from a state
  • Model: Agent's internal representation of environment dynamics
Design Implications

Model-free methods (Q-learning, Policy Gradient) learn without a model. Model-based methods can plan ahead but require accurate dynamics predictions. Value-based methods derive policies from Q/V, while policy gradient methods optimize π directly.

Exploration vs Exploitation

Tradeoff

The fundamental dilemma: exploit known good actions or explore potentially better alternatives?

No algorithm completely solves this — only manages the tradeoff.

  • Exploitation: Select action with highest known value
  • Exploration: Try suboptimal actions to discover better ones
  • Pure exploitation risks missing optimal solutions forever
  • Pure exploration wastes time on known bad actions
Common Strategy

The notes focus on ε-greedy: pick a random action with probability ε and greedy action otherwise. Schedules anneal ε downward as learning progresses.

Markov Decision Process

Framework

The formal mathematical framework for sequential decision-making under uncertainty.

MDPs formalize when history doesn't matter — only current state.

  • Markov Property: P(sₜ₊₁|sₜ,aₜ) = P(sₜ₊₁|s₀,...,sₜ,a₀,...,aₜ)
  • Episodic Tasks: Terminate at goal states (games, puzzles)
  • Continuing Tasks: Run indefinitely (robotics, trading)
  • Chess position is Markov; conversation context is not
Practical Implications

When true state isn't fully observable (POMDP), solutions include state estimation or frame stacking. LLM token generation treats prompt + generated tokens as state — approximately Markov with sufficient context.

Returns & Discounting

Theory

How future rewards are weighted and accumulated into a single objective.

Gₜ = Rₜ₊₁ + γRₜ₊₂ + γ²Rₜ₊₃ + ... = Σₖ γᵏRₜ₊ₖ₊₁
  • Return (Gₜ): Total discounted future reward from time t
  • Discount factor (γ): ∈ [0, 1], typically 0.99
  • γ → 0: Myopic agent, only immediate rewards
  • γ → 1: Far-sighted agent, values distant rewards equally
Why Discount?

Mathematical convenience (bounded sums), uncertainty about future, preference for sooner rewards, and preventing infinite returns in continuing tasks. In practice, γ encodes planning horizon.

02

Value Functions

Quantifying long-term goodness of states and actions — the foundation of value-based RL.

4 concepts
▼

State Value V(s)

Function

Expected return starting from state s and following policy π thereafter.

V_π(s) = E_π[Gₜ | Sₜ = s]
  • Answers: "How good is it to be in this state?"
  • Depends on which policy is being followed
  • Estimated by averaging returns over many episodes (MC) or bootstrapping (TD)

Action Value Q(s,a)

Function

Expected return for taking action a in state s, then following π.

Q_π(s,a) = E_π[Gₜ | Sₜ = s, Aₜ = a]
  • Answers: "How good is taking this action here?"
  • Key for control: Pick action with max Q(s,a)
  • Q-table: stores values for all (state, action) pairs
  • For greedy policy: Q(s,a*) = V(s)

Bellman Equation

Theory

The recursive relationship that decomposes value into immediate + future components.

V(s) = E[R + γV(s') | s]
  • Value = immediate reward + discounted future value
  • Foundation of DP, TD, and most RL algorithms
  • Optimality: V*(s) = maxₐ E[R + γV*(s')]
Computational Insight

Bellman equations turn the RL problem into a system of equations. DP solves them exactly (if model known), TD solves them by sampling, and neural networks approximate them for large state spaces.

Epsilon-Greedy Policy

Strategy

Simple exploration strategy balancing random and greedy actions.

  • With probability (1-ε): take best known action (exploit)
  • With probability ε: take random action (explore)
  • Typical schedule: ε = 1.0 → 0.01 over training
  • Goal is to maximize return Gₜ = Σₖ γᵏRₜ₊ₖ₊₁ (discounted sum of future rewards)
  • Ensures all actions tried, converges to optimal
03

Dynamic Programming

Model-based planning methods requiring known transition dynamics — theoretically optimal but often impractical.

5 concepts
▼

Policy Evaluation

Algorithm

Computing V_π for a given fixed policy — the "prediction problem".

V(s) ← Σₐ π(a|s) Σₛ',ᵣ P(s',r|s,a)[r + γV(s')]
  • Initialize V(s) = 0 for all states
  • Iterate Bellman updates until convergence
  • Requires known model P(s',r|s,a)

Policy Improvement

Algorithm

Making policy better given current value estimates.

π'(s) = argmaxₐ Σₛ',ᵣ P(s',r|s,a)[r + γV(s')]
  • For each state, find action maximizing expected return
  • Guaranteed to improve or maintain policy quality

Policy Iteration

Algorithm

Alternating evaluation and improvement until convergence.

  • 1. Start with arbitrary policy π₀
  • 2. Evaluate: compute V_π
  • 3. Improve: update π using V_π
  • 4. Repeat until policy stabilizes → π*

Value Iteration

Algorithm

Combined evaluation + improvement in one update step.

V(s) ← maxₐ Σₛ',ᵣ P(s',r|s,a)[r + γV(s')]
  • Uses Bellman Optimality Equation directly
  • More efficient than policy iteration
  • Converges to optimal V*

DP Limitations

Critical

Why practical RL requires learning methods instead of pure planning.

  • Requires complete model P(s',r|s,a)
  • Full state sweeps are O(|S|²|A|)
  • Impractical for large/continuous state spaces
  • Not learning from experience
Motivation for Model-Free RL

DP shows *what* the optimal solution looks like but not *how* to find it practically. MC and TD methods learn from samples without requiring the model.

04

Model-Free Methods

Learning from experience without knowing environment dynamics — Monte Carlo and Temporal Difference approaches.

5 concepts
▼

Monte Carlo Methods

Algorithm

Learn value by averaging complete episode returns — no bootstrapping.

V(s) ← V(s) + α[Gₜ - V(s)]
  • No model required — pure experience-based learning
  • Must wait for episode end to get Gₜ
  • Unbiased but high variance
  • Only works for episodic tasks

Temporal Difference (TD)

Algorithm

Learn after every step using bootstrapped estimates — the core of modern RL.

V(s) ← V(s) + α[R + γV(s') - V(s)]
  • TD Target: R + γV(s')
  • TD Error: δ = R + γV(s') - V(s)
  • Bootstrapping: estimates update estimates
  • Can learn before episode ends, works for continuing tasks
  • Lower variance than MC, some bias

SARSA (On-Policy)

Algorithm

TD control learning Q(S,A,R,S',A') — learns policy being followed.

Q(S,A) ← Q(S,A) + α[R + γQ(S',A') - Q(S,A)]
  • On-policy: learns about the ε-greedy policy it follows
  • Uses actual next action A' from current policy
  • Learns safer paths that account for exploration mistakes

Q-Learning (Off-Policy)

Algorithm

TD control using max Q — learns optimal policy while exploring.

Q(S,A) ← Q(S,A) + α[R + γ maxₐ Q(S',a) - Q(S,A)]
  • Off-policy: learns optimal Q* regardless of behavior policy
  • Uses max over next actions (greedy target)
  • Finds optimal but potentially riskier paths
SARSA vs Q-Learning

Classic example: cliff walking. SARSA learns safe route away from cliff (accounting for random exploration steps). Q-Learning learns shortest path along cliff edge (optimal if perfect execution).

On-Policy vs Off-Policy

Theory

Whose data generates learning — fundamental design choice.

  • On-Policy: Learn about policy generating the data (SARSA)
  • Off-Policy: Learn different policy from data (Q-Learning)
  • Off-policy enables learning from demonstrations, replay
  • Importance sampling corrects distribution mismatch

Function Approximation & Deep RL

Scaling to large state spaces with parameterized functions and neural networks.

6 concepts
▼

Linear Methods

Foundation

Simple parameterized value functions with convergence guarantees.

V̂(s,w) = wᵀx(s) = Σᵢ wᵢxᵢ(s)
  • Feature vector x(s) for each state
  • Learn weight vector w
  • Gradient: ∇V̂ = x(s) — simple and fast

Neural Network Approximation

Deep RL

Nonlinear function approximation enabling end-to-end learning from pixels.

  • Input: state (or raw pixels)
  • Output: V(s) or Q(s,a) for all actions
  • Backpropagation computes gradients
  • Universal approximation capability
  • Used in AlphaGo, RLHF, modern LLMs

Deep Q-Network (DQN)

Breakthrough

DeepMind's 2015 breakthrough — superhuman Atari from raw pixels.

Loss = (r + γ maxₐ' Q_target(s',a') - Q(s,a))²
  • CNN processes stacked frames (4×84×84) using three conv layers (8×8 stride4, 4×4 stride2, 3×3 stride1) followed by a 512‑unit fully connected head
  • Updates use Huber (smooth‑L1) loss with a separate target network and replay buffer
  • Typical hyperparameters from the paper: replay buffer 100 000, batch size 32, γ=0.99, lr=0.00025, ε annealed 1→0.1 over 1 M frames
  • Outputs Q-value for each possible action
  • Human-level performance on 49 Atari games

Experience Replay

Technique

Breaking temporal correlation by sampling from stored transitions.

  • Store transitions (s, a, r, s') in replay buffer (capacity ≈100 000 in original work).
  • Sample random minibatches (e.g. 32 samples) for training.
  • Breaks temporal correlation in data and makes each experience reusable.
  • Allows off-policy updates and stabilizes learning.
  • Essential for stable DQN training.

Target Network

Technique

Stabilizing training by fixing the bootstrap target.

  • Frozen copy of Q-network for computing targets
  • Updated every N steps (e.g., 10,000)
  • Prevents chasing a moving target
  • Critical for DQN stability

Frame Stacking

Technique

Capturing motion information from static observations.

  • Single frame: no velocity information
  • Stack last 4 frames as input
  • Agent can infer ball direction/speed
  • State becomes 4×84×84 grayscale tensor

Policy Gradient Methods

Direct policy optimization — foundation of modern RL for LLM alignment (PPO, RLHF, GRPO, DPO).

12 concepts
▼

Why Policy Gradient?

Motivation

Optimize policy directly instead of deriving it from value functions.

  • Value methods: learn Q → derive π greedily
  • Policy gradient: learn π_θ directly!
  • Better for continuous action spaces
  • Can learn stochastic policies
  • Foundation for RLHF in ChatGPT/Claude

Policy Gradient Theorem

Theory

The key insight making policy gradients tractable.

∇J(θ) ∝ E_π[Q(s,a) ∇ log π_θ(a|s)]
  • Key insight: No gradient through state distribution μ(s)
  • Score function: ∇ log π = ∇π / π
  • Enables estimation from samples

REINFORCE

Algorithm

First practical policy gradient — simple but high variance.

θ ← θ + α · Gₜ · ∇ log π_θ(aₜ|sₜ)
  • Use episode return Gₜ as Q estimate
  • High return → increase action probability
  • Simple but high variance
  • Must wait for episode end

Baseline & Variance Reduction

Technique

Subtracting value function dramatically reduces gradient variance.

θ ← θ + α · (Gₜ - V(s)) · ∇ log π_θ(aₜ|sₜ)
  • Baseline b(s) = V(s) is state-dependent only
  • Doesn't bias the gradient (proof: expectation zero)
  • Gₜ - V(s) = Advantage (better than average?)

Actor-Critic

Architecture

Combining policy gradient with TD learning — best of both worlds.

θ ← θ + α · δ · ∇ log π_θ where δ = r + γV(s') - V(s)
  • Actor: Policy π_θ (chooses actions)
  • Critic: Value V (evaluates states)
  • TD error δ replaces full return Gₜ
  • Can update every step, not just episode end

Advantage Function

Theory

How much better is this action than the average action in this state?

A(s,a) = Q(s,a) - V(s)
  • A > 0: action better than expected
  • A < 0: action worse than expected
  • A = 0: action is average for this state

GAE (Generalized Advantage Estimation)

Technique

Flexible bias-variance tradeoff via exponentially-weighted TD errors.

Â_GAE = Σₖ (γλ)ᵏ δₜ₊ₖ
  • λ=0: pure TD (high bias, low variance)
  • λ=1: pure MC (low bias, high variance)
  • λ≈0.95 typical in practice
  • Used in PPO, TRPO, modern algorithms

KL Divergence

Theory

Measuring distribution difference — critical for trust regions.

D_KL(P || Q) = Σₓ P(x) log(P(x) / Q(x))
  • Intuition: Surprise using Q when data comes from P
  • KL = 0 means identical distributions
  • Not symmetric: KL(P||Q) ≠ KL(Q||P)
  • TRPO/PPO: prevent policy from changing too much
  • RLHF: keep LLM close to base model

TRPO (Trust Region Policy Optimization)

Algorithm

Stable updates via constrained optimization with KL bound.

max L(θ) subject to D_KL(π_old || π_new) ≤ δ
  • Trust Region: Bound KL to prevent large updates
  • Guarantees monotonic improvement
  • Foundation for PPO and GRPO

PPO (Proximal Policy Optimization)

Algorithm

Simplified trust region via clipping — powers most RLHF systems.

L_CLIP = min(rA, clip(r, 1-ε, 1+ε)A) where r = π_new/π_old
  • Ratio r: π_new(a|s) / π_old(a|s)
  • Clipping: Limits how much π can change
  • Simpler than TRPO — no conjugate gradient
  • Used in ChatGPT, Claude, most RLHF systems
Industry Standard

PPO became the default for RLHF because it's stable, sample-efficient, and easy to implement. The clipping mechanism prevents catastrophic policy updates while still allowing meaningful learning.

GRPO (Group Relative Policy Optimization)

Algorithm

DeepSeek's critic-free method for LLM reasoning.

L = L_PPO - β · D_KL(π_θ || π_ref)
  • Key Innovation: No value function/critic needed
  • Group Advantage: Aᵢ = (rᵢ - mean(r)) / std(r)
  • Generate G responses, normalize within group
  • Perfect for verifiable rewards (math/code)
  • Powers DeepSeek-R1 reasoning
LLM Context

State = prompt + tokens so far. Action = next token. Rewards only at response end. By comparing multiple completions within a group, GRPO eliminates the need for a separate critic network.

RLHF (RL from Human Feedback)

Pipeline

Three-stage process aligning LLMs with human preferences.

  • Stage 1: SFT on human demonstrations
  • Stage 2: Train reward model on preference pairs (pairwise logistic loss)
  • Stage 3: Optimize policy with PPO + reward model
  • KL penalty: Prevents drifting from base model
  • Reward model: input prompt+response → scalar score; trained to rank preferred answer higher (Bradley–Terry style)
  • Watch out: reward hacking and domain shift can degrade RM quality
Powers Modern LLMs

RLHF is why ChatGPT feels helpful rather than just completing text. The reward model captures human preferences about helpfulness, harmlessness, and honesty.

Reward Model

Component

Neural network that scores candidate responses based on human preferences.

  • Inputs: prompt + candidate answer
  • Output: single scalar reward value
  • Trained on human-labeled preference pairs
  • Uses pairwise logistic (Bradley–Terry) loss: −log σ(s⁺−s⁻)
  • Architecture: text encoder with linear head (e.g. DeBERTa)
Usage

The RM guides PPO updates and can later evaluate model quality; good RM reduces reward hacking and ensures alignment.

DPO (Direct Preference Optimization)

Algorithm

Skip the reward model — train directly on preferences.

L = -log σ(β[log π_θ(y⁺|x) - log π_θ(y⁻|x) - ref_gap])
  • Key insight: Preferences as logistic regression
  • Increase probability of preferred response y⁺
  • Decrease probability of rejected response y⁻
  • No reward model needed — simpler pipeline
  • Used by Llama 2, Zephyr, many modern models
RLHF vs DPO

DPO shows the reward model is implicit in the policy itself. This simplifies training but may have less flexibility than explicit reward modeling for complex preference structures.
