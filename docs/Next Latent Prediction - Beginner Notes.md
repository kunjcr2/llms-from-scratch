# Next Latent Prediction — Beginner Notes

> Based on the transcript **“What’s Next: Latent Prediction?”**
>
> Note: The transcript was generated by speech recognition, so a few names and technical terms may be misspelled. The central idea is referred to below as **Next Latent Prediction (NextLat)**.

## 1. The big idea

Most modern language models are trained mainly to predict the next **token**—a small piece of text such as a word, part of a word, or punctuation.

Next Latent Prediction adds a second training task:

1. Predict the next token, as usual.
2. Also predict the model’s **next hidden state**—its next internal representation.

The second task encourages the model to keep a useful summary of the situation it is reasoning about. The researchers describe this summary as a **belief state** or a small **world model**.

The extra prediction network is used during training, but can be removed during normal generation. In other words, the model’s inference-time architecture stays almost the same; the additional objective changes what the transformer learns internally.

---

## 2. Why next-token prediction may be insufficient

### What a normal transformer does

At each position, a transformer uses **self-attention** to look back at the previous tokens. It then produces a hidden state and predicts what token should come next.

Because the model can repeatedly look back at the whole context, it does not always need to store a compact summary of what it has seen in its hidden state.

This can lead to a shortcut:

> “Instead of maintaining an internal model of the situation, I can look back through the context whenever I need information.”

That shortcut is often good enough for ordinary text prediction, but it can be weak for tasks requiring persistent state, planning, or understanding how a system changes over time.

### Beginner analogy

Imagine taking an open-book exam. A normal transformer can keep checking the entire book—the previous context—whenever it needs an answer.

NextLat adds pressure to also maintain a useful set of notes in its head. It must predict what its internal notes should look like after reading the next item.

---

## 3. What is a latent or hidden state?

A **latent state** is an internal vector used by the model. It is not directly readable text. It may encode information such as:

- where an object is in a map;
- which facts have already been established;
- whose turn it is in a game;
- what a variable currently equals;
- what the model expects to happen next.

The latent state is not necessarily a complete, human-readable description. It is more like a compact working memory that is useful for the model’s computation.

In this paper, the target is approximately the transformer’s **next final hidden state**—the representation immediately before the next-token prediction—not every intermediate activation inside the network.

---

## 4. How the training objective works

Let:

- `h_t` = the current hidden state;
- `x_(t+1)` = the next token;
- `h_(t+1)` = the transformer’s actual next hidden state.

The usual language-model loss asks the model to predict `x_(t+1)` from `h_t`.

NextLat adds a small multilayer perceptron (MLP) that receives the current state and the next token and tries to predict the next hidden state:

```text
current hidden state + next token
                  |
                  v
             small MLP
                  |
                  v
       predicted next hidden state
```

The predicted state is compared with the transformer’s actual next state. The actual target is treated as a fixed target for this auxiliary loss—this is what the transcript means by **stop gradient**.

The total training objective is conceptually:

```text
total loss = next-token loss + auxiliary next-latent loss
```

The auxiliary loss sends a training signal back into the transformer. It encourages the current hidden state to contain enough information to make the next state predictable.

### Why use a small MLP?

The MLP is not intended to be a second large language model. It is a lightweight transition function: given the current internal state and the next input, estimate the next internal state.

---

## 5. What happens during inference?

During ordinary decoding, the auxiliary MLP can be removed. The model still generates tokens using the transformer.

This is important because the method changes training without requiring a fundamentally different model at deployment time:

- same main transformer;
- same token-generation interface;
- no required auxiliary head during normal decoding;
- potentially better internal state tracking.

The MLP can also be used for **self-speculative decoding**: it can cheaply forecast several future latent states, allowing the expensive transformer computation to be used more efficiently.

---

## 6. Why this resembles an RNN

An RNN repeatedly updates a state:

```text
new state = transition(old state, new input)
```

NextLat trains an MLP to learn a similar one-step transition between transformer hidden states. The transformer itself still processes the sequence in parallel during training, so it does not become a traditional recurrent network.

This gives an interesting combination:

- the transformer provides powerful parallel processing;
- the learned latent transition behaves somewhat like recurrence;
- the model is encouraged to maintain state without explicitly feeding generated text back into itself.

One striking experiment described in the interview keeps the learned MLP and connects it recurrently. That smaller recurrent system can generalize in ways the original token-prediction model does not, suggesting that the MLP learned a meaningful state-transition rule.

This is evidence of a useful learned structure—not proof that the model has human-like understanding.

## 7. Experiments mentioned in the interview

### Manhattan taxi task — around 8:00

The model receives instructions about a taxi moving through a map and must track or reconstruct the underlying layout.

The reported result is that NextLat produces a cleaner and more compact internal representation than ordinary next-token prediction. The model appears better able to maintain a consistent map instead of merely producing locally plausible moves.

### Countdown/state-tracking tasks — around 9:00–13:30

These tasks require remembering a changing state across a sequence. Ordinary GPT-style models can perform reasonably on the sequence lengths seen during training but may fail when the sequence becomes longer.

NextLat reportedly generalizes better beyond the training length. This is exactly the kind of behavior the auxiliary objective is meant to encourage: preserve the state and update it consistently.

### Path-star graph planning — around 9:40

The model must plan through a graph. These tasks are difficult for a model that only learns local token patterns because the correct choice may depend on a larger structure.

The reported improvement suggests that NextLat can help the model represent the graph and plan over it, rather than simply imitate common short sequences.

### Speculative decoding — around 14:00

The learned latent transition can forecast multiple steps cheaply. The interview reports speedups of up to roughly three times in some settings.

This benefit was apparently discovered after the original belief-state motivation. It was not the initial reason for designing NextLat.

## 8. What “belief state” means here

In partially observed environments, an agent does not see the entire true world. It must maintain a belief about the current situation based on its observations.

For example, if a card is hidden, the agent may not know the card’s identity, but it can maintain probabilities over possible identities.

In this discussion, “belief state” is used more broadly: it means an internal representation that contains enough information about the past and current situation to predict what comes next.

It does not necessarily mean the model has conscious beliefs or a literal symbolic database.

---

## 9. Important distinctions

### NextLat is not the same as multi-token prediction

Multi-token prediction asks the model to predict several future tokens.

NextLat asks it to predict the next internal representation. The two methods can be related, and NextLat may also support faster multi-step decoding, but their training targets are different.

### It is not chain-of-thought

Chain-of-thought produces extra text tokens that are used as intermediate reasoning steps. NextLat tries to encourage intermediate computation in latent space, without requiring every step to be written out as text.

### It is not automatically a world model

Better state tracking and planning are evidence that the representation is useful. Calling it a “world model” is an interpretation of what the representation may be doing, not a guarantee that it contains a complete simulation of the real world.

## 10. Open questions and limitations

The interview raises several questions that are not fully settled:

- Does the method scale to very large frontier models?
- How much does it help on broad real-world language tasks rather than carefully designed synthetic tasks?
- Can it be added effectively during post-training, or must it be included during pretraining?
- How should researchers measure data efficiency at small scale?
- Does a compact latent state improve robustness, or only benchmark performance?
- How much of the reported inference speedup depends on the implementation and hardware?

The speakers also discuss a broader issue: small research models can show promising gains that disappear at larger scales. A small-scale result is encouraging, but it is not proof that the same method will improve a production-scale model.

---

## 11. Main takeaway

The central proposal is simple:

> Train a transformer not only to predict the next piece of text, but also to predict how its own internal state should evolve.

This extra pressure may encourage the model to develop a compact, persistent representation of the situation it is processing. The reported benefits include better state tracking, planning, length generalization, and faster speculative decoding.

The broader lesson is that the training objective strongly influences what information a model chooses to represent internally. If we want models to reason about changing situations, it may help to train them to predict changes in their internal state—not only changes in the text stream.

## 12. Beginner glossary

| Term | Plain-language meaning |
|---|---|
| Token | A small text unit processed by a language model. |
| Transformer | The neural-network architecture used by most modern language models. |
| Self-attention | A mechanism that lets each position use information from earlier positions. |
| Hidden state | An internal vector representing what the model currently knows or is computing. |
| Latent space | The internal numerical space where hidden representations live. |
| MLP | A small feed-forward neural network made of multiple layers. |
| Auxiliary loss | An additional training objective besides the main objective. |
| Stop gradient | A rule that prevents a target value from receiving gradient updates from a particular loss. |
| Belief state | A compact internal summary of the situation, especially when the full state is not directly visible. |
| World model | An internal model of how situations, objects, or environments behave. |
| Recurrence | Updating a state repeatedly over time. RNNs use recurrence explicitly. |
| Speculative decoding | Using a cheaper predictor to propose future outputs, then checking them with the main model. |
| Teacher forcing | During training, giving the model the correct previous token instead of its own sampled token. |
| Scaling | Increasing model size, data, or compute to test whether a method continues to help. |
