DETR — Detection Transformer

Architecture + training flow with tensor shapes. End-to-end object detection without anchors or NMS — from image to bounding boxes in one forward pass.

Step 1 · CNN Backbone (Feature Extraction)
🏗️
ResNet-50 Backbone
Pretrained CNN feature extractor · classification head removed
(B, 3, H, W) → conv1 + bn + relu + maxpool → layer1 → layer2 → layer3 → layer4 → (B, 2048, H/32, W/32) → 1×1 Conv2D → (B, 256, H/32, W/32)
  • ResNet-50 reduces spatial resolution by 32× (e.g., 800×1066 → 25×34)
  • Final conv layer outputs 2048 channels — rich semantic features
  • 1×1 convolution projects to transformer's hidden_dim = 256
  • Classification head (fc) is deleted — we only need the feature map
For an 800px input: feature map ≈ (B, 256, 25, 34) → 850 spatial tokens for the transformer
Add 2D position embeddings
Step 2 · Position Embedding (Learned Row + Column)
📐
2D Learned Position Embedding
Separate row and column embeddings concatenated per spatial position

Row Embedding:

row_embed: (50, 128)
Same row PE for every column in that row

Column Embedding:

col_embed: (50, 128)
Same column PE for every row in that column
col[:W] (1, W, 128) repeat H rows → (H, W, 128) || row[:H] (H, 1, 128) repeat W cols → (H, W, 128) → concat → (H, W, 256) → flatten → (H×W, 1, 256)
  • 128-dim row + 128-dim col = 256-dim total (matches hidden_dim)
  • 50 is an upper bound for feature map dimensions (both H and W are < 50)
  • PE is added to image features before entering the encoder
Flatten + feed into transformer
Step 3 · Transformer (Encoder + Decoder)
🔄
Transformer Encoder (×6 layers)
Self-attention over image feature tokens
(B, 256, H, W) → flatten + permute → (H×W, B, 256) → + pos embed → (H×W, B, 256)
  • Self-attention: every spatial token attends to all other tokens
  • Position embeddings added at every layer (not just once)
  • PE added to Q and K only, not V (preserves value content)
  • 6 layers of multi-head self-attention (8 heads)
  • Output: contextually enriched image features
PyTorch's nn.Transformer uses (seq_len, batch, dim) format — hence the permute to (H×W, B, 256)
🎯
Transformer Decoder (×6 layers)
Object queries cross-attend to encoder output

100 Learnable Object Queries:

query_pos: (100, 256)
  • Self-attention: 100 queries attend to each other (reason about objects' relationships)
  • Cross-attention: Q = object queries, K/V = encoder output
  • Each query "asks" the image: "is there an object like me here?"
  • Queries use learnable PE — no inherent spatial meaning
  • Keys use sinusoidal PE (from 2D image grid)
(100, 1, 256) → 6× (self-attn + cross-attn + FFN) → (100, B, 256) → transpose → (B, 100, 256)
Object queries start as 0 + learnable PE = PE directly. Each of the 100 output vectors represents one potential detection slot.
🔗 Encoder ↔ Decoder Connection

The encoder output (H×W, B, 256) serves as the Key and Value in every decoder cross-attention layer. Object queries (100, 1, 256) serve as the Query. This lets each object query "look at" the entire image to find its assigned object. During training, loss is computed on outputs from all decoder layers, not just the final one.

Parallel prediction heads
Step 4 · Prediction Heads (100 Parallel Predictions)
✨
Class + BBox Predictions
Each of 100 decoder outputs → one class + one bounding box

Classification Head:

(B, 100, 256) → Linear(256, 92) → (B, 100, 92)
  • 91 COCO classes + 1 "no object" (∅) class
  • Softmax over 92 classes at inference

Bounding Box Head:

(B, 100, 256) → Linear(256, 4) → sigmoid → (B, 100, 4)
  • Predicts (cx, cy, w, h) in [0, 1] normalized coords
  • Sigmoid ensures all values are in valid range
At inference, filter predictions where "no object" class has highest probability. Remaining predictions are final detections — no NMS needed.
Match predictions to ground truth (training only)
Step 5 · Hungarian Matching + Set Loss
🔀
Bipartite Matching (Hungarian Algorithm)
Optimally assign each prediction to one ground truth — one-to-one, no duplicates
σ̂ = argminσ ∑iN Lmatch(yi, ŷσ(i))
  • N = 100 predictions, M ground-truth objects (M < 100)
  • Pad ground truth with (100 − M) "no object" labels
  • Build cost matrix: matching cost for every (prediction, GT) pair
  • Hungarian algorithm finds the optimal one-to-one assignment
  • Each prediction matches to exactly one GT (or ∅) — no duplicate detections
📋
Classification Loss
Cross-entropy on matched pairs
Lcls = CE(ŷclass, yclass)
  • Penalizes wrong class assignments
  • "No object" class handles unmatched slots
📏
L1 Box Loss
Per-coordinate distance
LL1 = |cx−ĉx| + |cy−ĉy| + |w−ŵ| + |h−ĥ|
  • Absolute error on normalized coords
  • Simple but sensitive to box scale
📐
Generalized IoU Loss
Scale-invariant overlap metric
LGIoU = 1 − IoU + |C \ (A∪B)| / |C|
  • C = smallest enclosing box of prediction & GT
  • Unlike IoU, penalizes non-overlapping boxes too
Ltotal = λcls · Lcls + λL1 · LL1 + λGIoU · LGIoU
Loss is computed on outputs from all 6 decoder layers and summed (auxiliary decoding losses help with training convergence).
⟲
Gradients flow end-to-end: Prediction Heads → Transformer Decoder → Transformer Encoder → 1×1 Conv → ResNet Backbone. The ResNet backbone starts ImageNet-pretrained and is fine-tuned. The transformer, prediction heads, object queries, and position embeddings are all trained from scratch. Training requires 300+ epochs on COCO — significantly longer than CNN-based detectors.

Design Decisions · Why?
1 Why object queries instead of anchors? ▼

Anchor boxes require hand-tuning (how many, what aspect ratios, how densely spaced). Object queries are fully learned — the model discovers what "slots" to allocate. Each query specializes (e.g., one query tends to detect objects in the top-left, another focuses on large objects). This removes a whole category of human engineering.

2 Why Hungarian matching instead of IoU-based NMS? ▼

NMS is a greedy heuristic — it suppresses overlapping boxes based on an IoU threshold, which can accidentally remove valid detections of nearby objects. Hungarian matching finds the globally optimal one-to-one assignment between predictions and ground truth. Each prediction matches exactly one object — duplicates are structurally impossible.

3 Why 100 object queries? ▼

100 is an upper bound on the maximum number of objects per image in COCO. Most images have far fewer objects, so most queries learn to predict "no object" (∅). The number is a hyperparameter — increasing it handles denser scenes but adds computation. Decreasing it risks missing objects in crowded images.

4 Why GIoU loss instead of plain IoU? ▼

Standard IoU is 0 for non-overlapping boxes regardless of how far apart they are — useless gradient signal. GIoU subtracts the fraction of the enclosing box that's empty, so even completely separated predictions get a distance-aware gradient pushing them toward the target. Combined with L1 loss, it covers both coordinate accuracy and overlap quality.

5 Why does DETR need 300+ epochs to train? ▼

The transformer decoder starts with random object queries that have no spatial prior (unlike anchors which start at known grid positions). The model must learn from scratch where to look and what to specialize on. This "cold start" requires many epochs for the attention patterns to stabilize. Variants like Deformable DETR reduce this by limiting attention to a learned sparse set of spatial positions.

6 Why row + column position embeddings? ▼

A single 1D position embedding loses 2D spatial structure. Separate row and column embeddings (128-d each, concatenated to 256-d) preserve the grid layout: two positions in the same row share the same row embedding, two in the same column share the column embedding. This gives the transformer explicit 2D spatial awareness without the overhead of a full 2D PE matrix.

7 The mental model that makes DETR click ▼

Think of 100 object queries as 100 detectives sent to investigate an image. Each detective starts with no clue (random initialization). Through 6 rounds of cross-examination (decoder layers), each detective "interrogates" the image features (via cross-attention) and coordinates with other detectives (via self-attention) to avoid duplicating work. By the end, each detective either reports an object or says "nothing found" (∅).
