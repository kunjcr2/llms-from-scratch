Step 1 · Training Data
📦
SA-1B Sample
Pick 1 image + 1 ground-truth mask
  • 11M images, 1.1B masks (~100 masks/image)
  • Each training step picks one image and one GT mask for a single object/region
Image: (3, 1024, 1024)
GT mask: (1, 1024, 1024)
GT = ground truth — a human-annotated or engine-generated binary mask
🎯
Simulate a Prompt
No human clicks during training — prompts are derived from GT mask
  • Point: sample random (x, y) inside GT mask region. Label = foreground.
  • Box: compute tight bounding box around GT mask, add random jitter to corners.
  • Mask: use output logits from a previous iteration as coarse mask input (iterative refinement).
This teaches the model to respond to the same kinds of signals real users give at inference.
Feed into architecture
Step 2 · Architecture (Three Components)
🖼️
(1) Image Encoder
MAE-pretrained ViT · runs once per image
(3, 1024, 1024) → patch 16×16 → (4096, 768) → ViT blocks → (4096, 1280) → reshape → (1280, 64, 64) → 1×1 conv → (256, 64, 64)
  • Heaviest component (~632M params for ViT-H)
  • All 4096 spatial tokens preserved (no CLS-only output)
  • Output cached — prompt changes don't re-run this
MAE pretraining: mask 75% of patches → reconstruct → learns deep image understanding without labels.
📍
(2) Prompt Encoder
No transformer — just embeddings + convolutions

Sparse Branch (points + boxes):

  • Point: (x,y) → positional encoding + type embedding → 256-d
  • Box: 2 corners → 2 tokens, each with distinct type embedding
  • 3 type embeddings total: foreground, background, box-corner

Dense Branch (mask):

(1, 1024, 1024) → Conv2D ×3 → (256, 64, 64)

Output Tokens (like DETR's object queries):

  • 3 mask tokens → become 3 output masks (multi-granularity)
  • 1 IoU token → becomes IoU confidence scores
Sparse out: (N + 2M + 4, 256)
Dense out: (256, 64, 64)
🎭
(3) Mask Decoder
Lightweight transformer · fast per prompt (~50ms CPU)

2× Bidirectional Cross-Attention Blocks:

  • Self-attention among token sequence
  • Token → Image cross-attention (Q=tokens, K/V=image)
  • Image → Token cross-attention (Q=image, K/V=tokens)
  • + one final token-to-image cross-attention

Mask Generation:

3 mask tokens → 3× MLP → 3 × (256,) → dot product w/ upscaled image → 3 × (1, 1024, 1024)
Image feats (256, 64, 64) → 2× TransposeConv → (256, 256, 256)
IoU token → MLP → 3 IoU scores
🔗 How components connect

Dense mask embedding (256, 64, 64) is element-wise added to the image embedding (256, 64, 64) before entering the decoder. Sparse tokens (N+4, 256) enter the decoder as the token sequence. The image embedding is flattened to (4096, 256) for attention.

Step 4 · Training Loss
📉
Choose-Best-Mask Loss
Compare each of 3 masks to GT, backprop only through the best match
i* = argmini∈{0,1,2} L(Pi, G)
This lets the 3 heads specialize (global / mid / local) instead of fighting each other. Only the best mask gets gradient signal.
🎯
Mask Loss (pixel + overlap)
Applied to the selected best mask only
Lmask = 20 · Lfocal + 1 · Ldice
  • Focal loss: modified BCE that down-weights easy background pixels and up-weights hard boundary pixels. Fights the class imbalance problem (>95% pixels are background).
  • Dice loss: directly optimizes mask overlap. 1 - 2|P∩G| / (|P|+|G|). Rewards boundary quality.
📊
IoU Prediction Loss (self-critique)
Teaches the model to estimate its own mask quality
Liou = MSE( IoUpred[i*], IoUactual(Pi*, G) )
  • Actual IoU is computed on-the-fly: |P∩G| / |P∪G|
  • At inference, use predicted IoU to auto-select the best mask
  • Makes SAM self-calibrating — it knows how good its own output is
Ltotal = 20 · Lfocal + 1 · Ldice + 1 · Liou
⟲
Gradients flow end-to-end through Mask Decoder → Prompt Encoder → Image Encoder. Image encoder starts MAE-pretrained (fine-tuned with small LR). Prompt encoder and mask decoder are trained from scratch. The 4 learnable output tokens (3 mask + 1 IoU) are also learned from scratch.
🔄 Iterative Refinement (training trick)

Pass 1: point/box prompt → predicted mask. Pass 2: feed Pass 1's mask logits back as a dense mask prompt → refined mask. Loss is computed on the refined mask. This teaches the model to take a rough mask and improve it — critical for the semi-auto annotation stage.

Design Decisions · Why?
1 Why prompts instead of fixed classes? ▼

Classic segmentation hard-codes a label space (cat/dog/…). SAM learns f(image, prompt) → mask, making it class-agnostic. It doesn't need to know object names to draw boundaries — just "select this region."

2 Why 3 masks per click? ▼

One point is ambiguous. Clicking a bird's head could mean head, body, or entire bird. Multi-mask output turns ambiguity from a bug into a feature. The "choose-best-mask" training rule lets heads specialize without averaging into mush.

3 Why the IoU prediction head? ▼

Users need to auto-select "the good mask." Training with MSE(pred, actual) makes SAM self-calibrating. At inference: click → 3 masks → pick the highest predicted IoU. Instant, no human needed.

4 Why MAE-pretrain the image encoder? ▼

MAE forces the ViT to understand images by reconstructing masked patches — strong general visual features without any labels. SAM fine-tunes this, getting world understanding + promptable masks without labeling every object class.

5 Why simulate prompts during training? ▼

Human clicks are expensive and inconsistent. Generating prompts from GT masks (sample points inside, derive boxes, feed rough masks) turns static mask data into interactive training examples. The model learns to respond to the same signals real users give.

6 Why combine focal + dice loss? ▼

Masks are extremely imbalanced (mostly background). Focal loss prevents the trivial "predict all background" cheat. Dice loss directly rewards overlap quality — what we actually care about visually. Together they cover per-pixel accuracy and global overlap.

7 The mental model that makes SAM click ▼

Think of SAM as two cached worlds meeting in the decoder: World A = image embedding (what's where — computed once). World B = prompt tokens (what you mean — cheap to change). The decoder is the translator: "Given World A and what the user means, paint the pixels."
